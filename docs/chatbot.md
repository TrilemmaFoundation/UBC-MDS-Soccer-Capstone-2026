# Django Chatbot Partner Guide

This guide covers how to run, update, and debug the Football Analytics LLM Chatbot (powered by Groq and BigQuery).

## 1. How to run the Chatbot

The chatbot is a Django web application that lives in the `app/` directory.

### Running locally (without Docker)
This is recommended for fast development and testing changes to the prompt or schema.

```bash
# 1. Activate your environment
conda activate soccer_capstone

# 2. Ensure credentials are set
# The chat service account requires the 'BigQuery Data Viewer' and 'BigQuery Job User' roles
export GOOGLE_APPLICATION_CREDENTIALS=./chat-service-account-key.json
# (Make sure GROQ_API_KEY is set in your .env file and loaded)

# 3. Navigate to the app directory
cd app

# 4. Apply database migrations (first time only)
python manage.py migrate

# 5. Start the development server
python manage.py runserver
```
The chatbot will be available at http://localhost:8000.

### Running via Docker
This is recommended for running the full stack or deploying.

```bash
# Ensure .env and chat-service-account-key.json are in the project root
# Start the chatbot container
docker compose up django-env
```
The chatbot will be available at http://localhost:8000.

## 2. How to update `table_schema.py`

When you add new mart tables in dbt, or add new columns to existing marts, you **must** update the chatbot's awareness of them so the LLM can generate correct SQL.

1. Open `app/chatbot/table_schema.py`.
2. Locate the `TABLE_CONTEXT` variable.
3. Follow the existing format to add your new table or columns.
    *   Include the full table path: `` `{_PROJECT_ID}.dbt_marts.your_new_table` ``
    *   Provide a short `Description` of what the table contains.
    *   List the `Core Columns` and their data types.
4. **Note:** The LLM is highly dependent on this file. Be explicit about grain rules (e.g., "One row per player-season") and edge cases.

## 3. How to update the system prompt

The system prompt dictates how the LLM behaves, formats its output, and interacts with the tool-calling loop.

1. Open `app/chatbot/llm_engine.py`.
2. Locate the `ask_football_chatbot` function.
3. Find the `messages` list, specifically the dictionary with `"role": "system"`.
4. Modify the content to change its persona or add new constraints.
5. **Important:** If you add new rules, add them to the `CRITICAL RULES` section and keep them numbered for the LLM to follow them strictly.

## 4. Using Advanced Mode for Debugging

If the chatbot gives an incorrect answer, hallucinates data, or errors out, **Advanced Mode** is your primary debugging tool.

1. In the chat interface, check the **"Advanced Mode (Show SQL query & raw data)"** box before submitting your question.
2. When the AI responds, two additional panels will appear below the message:
    *   **Executed SQL Query:** The exact SQL statement generated by the LLM.
    *   **Raw BigQuery Data:** The raw JSON rows returned by the BigQuery client.

**How to use this information:**
*   **Wrong data returned?** Copy the SQL from Advanced Mode and run it directly in the BigQuery console. Check if the LLM joined the tables incorrectly or forgot a `WHERE` clause.
*   **LLM ignored data?** Check the "Raw BigQuery Data" panel. If the data is there but the LLM didn't format it, the fallback logic in `llm_engine.py` might need tweaking, or the system prompt needs stronger instructions to output the data.

## 5. The `is_safe_sql()` Security Layer

Because the LLM generates SQL that is executed against your BigQuery project, a security layer prevents destructive actions or prompt injections.

The validation function is located in `app/chatbot/llm_engine.py`. It works by:
*   **Blocking multi-statement queries:** Rejects any string containing a semicolon (`;`).
*   **Blocking DML/DDL:** Scans for and rejects keywords like `DROP`, `DELETE`, `UPDATE`, `INSERT`, `MERGE`, `CREATE`, `ALTER`, `GRANT`, `TRUNCATE`, etc.
*   **Enforcing Read-Only commands:** Ensures the query strictly starts with `SELECT` or `WITH`.

If you need to allow a new specific SQL function that gets falsely flagged, or block a new keyword, modify the `forbidden_keywords` list or the regex checks within the `is_safe_sql` function.

## 6. Common Failures and Diagnostics

| Symptom | Diagnosis & Fix |
| :--- | :--- |
| **"Database query rejected: Unauthorized SQL statement structure."** | The LLM generated a query that failed `is_safe_sql()`. Turn on Advanced Mode, look at the SQL. If it added a semicolon, update the prompt to say "Do not use semicolons". |
| **"An error occurred while fetching the requested statistics."** | The generated SQL was invalid BigQuery syntax (e.g., hallucinated a column). Turn on Advanced Mode, copy the SQL, run it in BigQuery UI to see the exact error. Update `table_schema.py` if the LLM is confused about the schema. |
| **Response says "No results found" but you know data exists.** | The LLM likely filtered out the data (e.g., applied a `minutes_played >= 270` filter that excluded your target player). Review the SQL in Advanced Mode. |
| **Chatbot hangs or takes a long time.** | The Groq API might be rate-limiting, or the BigQuery job is scanning too much data. Check your terminal logs for Groq fallback messages (`Retrying with fallback model...`). |
