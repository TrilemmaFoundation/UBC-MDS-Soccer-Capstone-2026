## Application

The final product is deployed as a unified Django web application that integrates a granular, AI-powered chatbot with a high-level visual dashboard. This architecture allows users to seamlessly transition between high-level exploratory data analysis and highly specific, ad-hoc natural language querying.

### Django Chatbot Architecture

The core of the application is an intelligent chatbot designed to translate user queries into precise BigQuery SQL statements, execute them, and return formatted analytical insights. 

* **Groq LLM Tool-Calling Loop**: The chatbot is powered by Groq's fast inference engine. It utilizes a primary model (`llama-3.3-70b-versatile`) for robust instruction following and falls back to a faster model (`llama-3.1-8b-instant`) if necessary. The LLM is initialized with a strict system prompt containing the `TABLE_CONTEXT` (a detailed schema of the dbt marts). When a user asks a question, the LLM determines if it needs data and utilizes a registered tool (`query_bigquery`) to generate a valid BigQuery Standard SQL SELECT statement. The app then executes this tool call, feeds the retrieved raw data back to the LLM, and forces the LLM to format the output directly into a readable list or table.
* **BigQuery Integration**: The application uses the Google Cloud BigQuery Python client to connect directly to the `dbt_marts` dataset.
* **`is_safe_sql` Security Layer**: To prevent prompt injection and unauthorized database manipulation, all LLM-generated SQL passes through a custom `is_safe_sql` validation layer before execution. This function strips out multi-statement queries (blocking semicolons) and ensures the string strictly starts with safe read-only commands (`SELECT` or `WITH`). Furthermore, it actively scans for and blocks destructive DDL/DML keywords, including `DROP`, `DELETE`, `UPDATE`, `INSERT`, `MERGE`, `CREATE`, `ALTER`, and `TRUNCATE`. If a query fails these checks, execution is immediately blocked.

### Advanced Mode Debug Feature

To build trust in the LLM's outputs and assist analysts with verifying data provenance, the chat interface includes an "Advanced Mode" toggle. 

When enabled, the application bypasses the standard conversational output to reveal the underlying mechanics of the tool call. The UI renders two additional debug panels:
1.  **Executed SQL Query**: Displays the exact SQL statement generated by the LLM. 
2.  **Raw BigQuery Data**: Outputs the raw JSON response returned by the BigQuery client.

This feature is critical for technical users who want to validate the logic of the LLM (e.g., ensuring it applied the correct minutes-played filters or per-90 normalizations) or for developers debugging model hallucinations.

### Looker Studio Dashboard

While the chatbot handles ad-hoc, granular queries, the visual dashboard serves as the platform for standardized tracking and exploratory analysis. 

* **Embedded Iframe Approach**: The dashboard is built natively in Looker Studio and is integrated into the Django application using a responsive iframe wrapper. The Looker Studio URL is injected dynamically into the `dashboard.html` template via Django settings, ensuring secure cross-origin embedding while allowing the dashboard to scale to the user's viewport.
* **Navigation**: The application utilizes a persistent, shared top navigation bar. This ensures a cohesive user experience, allowing analysts to instantly toggle between the visual dashboard interface and the chatbot interface without losing their workflow context.

### User Flow Walkthrough

The integration of these tools creates a powerful, end-to-end workflow for a football analyst:

1.  **Exploration**: The analyst begins on the **Dashboard**, browsing the charts and tables to identify high-level trends. For example, they might notice a cluster of "Creative Wingers" overperforming their xG in the player scatter plots.
2.  **Investigation**: Seeking more specific, granular details that aren't hardcoded into the visual dashboard (e.g., "Which of these top 5 creative wingers in La Liga also have the highest defensive pressures per 90?"), the analyst clicks the top navigation link to switch to the **Chatbot**.
3.  **Ad-Hoc Querying**: The analyst types their natural language question. The LLM processes the request, writes the custom SQL, queries BigQuery, and returns a formatted top 5 list. 
4.  **Verification**: The analyst toggles **Advanced Mode** to review the exact BigQuery SQL syntax generated by the LLM, verifying that the appropriate tables (`mart_player_performance` and `mart_player_clusters`) were joined and the correct filters were applied.
